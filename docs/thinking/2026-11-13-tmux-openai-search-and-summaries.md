# tmux 摘要、命名与轻量搜索

2026-11-13。已按用户确认的方向实施首版：云端生成摘要和搜索关键词，本地模糊搜索。不部署本地模型，不调用 embedding。

## 决定与原因

用户希望输入“call-e overwrite”或“配置覆盖”找到正在推进的窗口，同时避免为少量窗口常驻数百 MB 模型内存。首版用同一次摘要请求生成 3–8 个中英文搜索关键词，保留原始标题、分支和路径，交给现有 fzf 模糊匹配。

这不是完整的语义检索：未出现在原文或生成关键词里的新表达仍可能无法命中。先收集实际漏检样例，再判断是否需要远程 embedding。搜索时没有模型调用或网络等待。

## 模型和凭据

- 摘要、next action、自动命名、关键词：`gpt-6-luna`，Responses API，`reasoning.effort=none`，严格 JSON Schema。
- 使用环境变量 `OPENAI_API_KEY_PRO_CREDIT`；未设置时只解析 `~/.env` 同名字段，不执行文件、不覆盖全局 `OPENAI_API_KEY`。
- 不修改交互式 Codex/Claude 的登录配置。

GPT-6 Luna 支持所需结构化输出，标准输入/输出单价为每百万 tokens $0.10 / $0.50。本地模型访问权限和实际延迟需要真实调用确认。[官方模型说明](https://developers.openai.com/api/docs/models/gpt-6-luna)

订阅赠送额度绑定领取额度的 API organization，并会按账期到期。它支持 API Platform 使用，但不支持通过 API key 使用 Codex。额度耗尽后，组织已有付费额度可能继续被消费，因此自定义变量名并不能保证只消耗赠送额度。[官方额度说明](https://developers.openai.com/api/docs/guides/chatgpt-api-credits)

## 实现结构

`tmux/openai_client.py` 替代 `codex_batch.py`，通过 Python 标准库直接发送 HTTPS 请求，不启动临时 Codex 进程。Task Board 和独立命名入口共用它。

Task Board 一次只允许一个后台请求，不建立无限队列。主循环继续发布状态；新任务的标题、路径或分支与请求时不同时，丢弃旧结果。终端继续输出时保留原始摘要 hash，使陈旧摘要仍可被识别。改名落地前重新检查窗口上下文与名称，用户手动改名优先。

普通摘要仍为 5 分钟周期，状态变化保留 60 秒通道。命名上下文稳定 10 秒后允许提前触发，完成命名请求后间隔至少 30 秒；首版复用同一摘要请求生成名称与关键词，不另做命名专用队列。linked sessions 下的同一物理 pane 去重。

每个 pane 采集近期 40 行，并截断至 6,000 字符；过滤控制字符和常见凭据格式。该过滤不是完整 DLP，终端近期内容仍会发送至 OpenAI。日志不记录 prompt、完整回复或密钥。请求 `store=false` 不等同于服务端零保留。

请求超时默认 30 秒，失败保留缓存，沿用 daemon 的有限频率退避，不在单个请求内循环重试。结构化结果拒绝、截断或校验失败不会覆盖旧摘要。[结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs)

## 搜索交互

继续使用 `prefix + g`。窗口树、pin、数字定位、Tab 切 pane、跨 client 跳转保持现有逻辑。

每个 pane 的可搜索资料包括：摘要、next action、原始会话标题、终端标题、窗口所属分支、完整路径和生成关键词。旧缓存缺少关键词时会在正常摘要调度中补齐；生成失败时原始字段仍可搜索。

展示与搜索分离：第 3 列仅展示简短任务信息，第 12 列保存完整搜索资料。`goto_search.py` 对打开面板时缓存的记录调用本地 fzf 做模糊匹配，外层 fzf 仅展示第 3 列；匹配的 pane 保留父窗口；搜索时按窗口组相关性排序，窗口名/项目目录中的连续匹配优先于摘要提及和模糊子序列匹配，同级沿用 fzf 排名。清空查询恢复原来的 pin/窗口顺序，输入查询时光标定位第一组。完整路径、分支、关键词在 `ctrl-/` 预览中查看。默认 shell 提示符标题不再占据列表行。搜索不发起网络请求。

例如“Calling 配置覆盖方案”可附带 `call-e`、`calling`、`overwrite`、`override`、`配置覆盖`。关键词依据当前任务生成，不建立全局强制同义词规则；每条最多 8 个，每个最多 64 字符。

## 预算与资源

无本地模型权重、向量库或独立模型服务；仅现有 Python daemon 增加一个按需工作的线程及小型关键词缓存。

初始本地预算为 $1/天、$20/月，使用本地日历日/月。请求前按输入字节与最大输出预留费用，成功后按 usage 对账；未知结果保留预留费用。默认费率保守计入输入 1.25 倍系数，不将缓存折扣算作节省。

共享账本：`~/.cache/tmux-openai/usage.json`（遵循 `XDG_CACHE_HOME`）。记录请求数、当日/月估算费用、最近模型、tokens 和耗时。锁防止独立命名与面板同时请求。此预算只限制本工具，不是账户余额或组织级硬限额。

配置项：`TMUX_OPENAI_MODEL`、`TMUX_OPENAI_DAY_BUDGET`、`TMUX_OPENAI_MONTH_BUDGET`。自定义模型时应同时调整 `TMUX_OPENAI_INPUT_USD_PER_M` 和 `TMUX_OPENAI_OUTPUT_USD_PER_M`，避免费用低估。

## 验证与边界

自动验证覆盖凭据优先级、安全解析、请求结构、费用上限、结构化错误、旧结果丢弃，以及真实 fzf 对中文、英文关键词、分支名的匹配。结合现有 Task Board、命名、pin 和导航回归测试。

运行验证需确认 key/模型可用、面板能写入关键词、daemon 持续刷新。本地搜索目标 P95 <100ms，命名目标在稳定变化后正常网络下 P95 <45 秒；这两个值是后续体验验收目标，不是已测指标。模型质量以用户实际漏检样例继续评估。

## 简化复核

保留一个生成模型、一个 API 客户端和现有 fzf。移除原方案的 embedding、SQLite 向量缓存、语义模式切换、排名融合；不引入本地推理服务、LLM reranker 或自动昂贵模型升级。
